## 素材获取与生成

**先复用现有机械美术，不换全套风格。** 主角、四类小怪、巡检机、HUD、商店卡框和 M2 音效作为母版。沿用 [M2 美术清单和图集流程](https://github.com/YaHu-Lee/night-shift-repair/blob/113cdaca614aad86194eab1c212b2d7cf82f49c6/docs/MECHANICAL-ART.md)，以现有 360×640 设计坐标做对齐。第一章先以灰盒完成可读性；确认好玩再换最终图，待产的插画不阻塞关卡。

| 优先级 | 交付 | 获取与制作 |
| --- | --- | --- |
| P0 战斗可读 | 4 套场地主题、可拼复用件、4 个章末 Boss 的辨识标记、6 枚首通武器图标、目标与危险提示、关键音效 | 批量复用现有母版；用矢量或程序化图形做预警边界和方向，人工校对锚点及透明留边；Boss 骨架可复用，攻击预警不能只换色 |
| P1 叙事与发行 | 阿阮／陈栖头像、复电终幕、封面和商店截图 | 以自有角色设定和构图生成草图，筛选后人工修边、统一比例和色板；不让生成模型出界面文字或关键战斗提示 |
| 不进入 MVP | 全配音、逐关插画、长动画过场 | 保留字幕、电台提示音和场景状态变化 |

**免费补缺。** 优先复用 [Kenney CC0 素材](https://kenney.nl/support)的通用 UI、粒子和短音效，沿用仓库已有 [Lucide 许可](https://lucide.dev/license)资源；字体先测系统中文字体，缺字或端差再测试 [思源黑体 OFL](https://github.com/adobe-fonts/source-han-sans/blob/master/LICENSE.txt)及子集的字库与许可要求。此前的[免费素材清单](ASSET-SOURCES.md)作为备选，不混进风格不同的整包。

**入库门槛。** 每件资产记录稳定 ID、路径、来源、原始许可、作者、校验值、派生关系、署名和再分发限制。生成资产另记工具、日期、生成描述和有权使用的参考图；不使用可识别第三方 IP 或权利不明的输入。能装进商业游戏，不等于能把原包上传到公开 GitHub。无再分发权的源档不入公开仓库；许可或生成来源不明确先用灰盒备件替代。用同一脚本生成可重建的图集与帧映射，保留 Cocos `.meta`，真机检查小尺寸轮廓、命中范围一致、色弱提示及静音可辨。

## 关卡制作与内容数据

**一个通用战斗场景，20 张配置，不是 20 个 Scene。** 场地模板用障碍、通道、出生点、危险区和目标点组成。首版只做四个目标模板：清波生存、切换供电区、护送载具、中继防守。Boss 用阶段加行为组件实现；05／10／15／20 各有不同解法，普通工单用现有 Boss、变体精英或强化敌群收尾。小怪压力主要靠队形、时序和协同提升，例如装甲挡弹加炮台封路，而不是同步加血加伤。

内容表用 Git 中可审阅的 JSON 作为唯一来源。关卡表负责前置、波表、目标、敌群和胜负；剧情表只引用事件，奖励表只引用武器与掉落 ID；场地和图集引用注册表键。策划可在表格里算预算，但不维护另一套运行时数值。先用小型热重载／调试面板选关、跳波、锁种子、显示碰撞与危险区；不先造完整编辑器。

```json
{
  "id": "c01_s02", "requires": ["c01_s01"], "arena": "pump_room",
  "waveSet": "pump_room_02", "objective": "clear_waves",
  "modifiers": ["alternating_live_puddles"], "finalEncounter": "pump_elite",
  "story": {"brief": "s02_brief", "clear": "s02_clear"},
  "firstClearReward": "hydraulic_nailer", "revivePolicy": "midwave_if_restorable",
  "targetSeconds": 360
}
```

字段示例是配置契约，不是现有文件。CI 校验 ID 唯一、前置无环且从首关可达、资产和文本引用存在、章末终局唯一、奖励可以获得、波次目标可结束、文本有跳过或回看路径。关卡评审必须回答：这一关迫使玩家换哪条路或换哪种构筑？读不出来，就先改遭遇，不用换皮补数。每关提交配置、两种配装的无广告通关记录、主要死因和真机截图。

## 局内构筑与局外成长

局内仍是双工具、模组配对与波间零件商店，胜负后清空当局零件和装配。局外只做两条：**主线首通免费获得 6 件工具；维修凭证定向换 3 张可选蓝图**。凭证、蓝图和可选挑战不挡主线，不做永久叠攻击、抽卡、体力或多币种。可选委托和加班挑战让位给 20 关完整交付。第一关默认保留原起手；02 起允许选择已解锁工具做首槽，第二槽照旧走局内获得。实现时要把「允许的首槽及起手模组」做成关卡／配装规则，同时改开局、快照校验、掉线恢复和首店保底，不能只改界面。

六件工具按 01／02／05／10／15／20 授予。数值定位是场景优势：电弧枪清群，液压钉枪打短弱点与护甲，脉冲喷管控近身，牵引线圈拆阵型，分束探针覆盖多路，旁路扳手近距离爆发。前两件先在 02 和 03 证明差异。每个关键关有基础工具可行解；每次结算在一个画面提供「带新武器继续」和「换装备」，不让玩家去商店碰掉落。

## 剧情演绎与文案交付

用工单、短电台字幕和战场反馈讲同一件事：玩家在听到问题后亲手解决。01 查出主动切电；06–10 把救援电池送回医院；11–15 让真实求救重新播出；16–20 接管供电。供电区亮起、电池入站、广播恢复和终局亮灯分别承担叙事结果，不把重要进展藏进小作文。首篇收束；港区回信只在尾声新增节点，不要求重开存档。

交付量为 20 条开场工单、20 条结单回执、8 条关键电台对话和 1 个终幕。运行时每条记录文本 ID、触发时机、说话人、优先级、仅首通／可重放和字幕键。遮挡 Boss 预警或打断手势的中途提示延迟播；公告离场及重复回调须去重。跳过只影响播放，不跳过任务完成、线索记录或奖励。用现有 HUD 覆盖层做可暂停和回看的档案页，不用自制复杂分镜系统。

## 数值策划与两小时门槛

**先锚定 M2 实测，不直接把当前计时乘 20。** 逐关填写波时、出怪间隔、峰值同屏、目标失败条件、精英可输出窗口、零件下限及店价。首版可用相对威胁点做波表对比：爬虫 1、冲车 2、炮台 3、护甲机 3；引入新机制时先维持前一关相近总压，再从不同方向或不同节拍增加压力。权重是起测假设，不能代替真机走位。Boss 用阶段暴露时间与玩家的有效输出校准，少用单纯加血；有效 DPS 估算可用「每发伤害 × 每秒攻击次数 × 命中率 × 平均命中目标数 × 可输出时间占比」。

**首店保底可验证。** 用一批固定种子与几种简单移动策略跑无界面模拟，筛查坏组合、平均与偏低零件收入、峰值同屏、基础工具软锁；第一次商店至少有一个能用低段位实际收入购买的有效配对，不以满拾取收入定价格。随后用人测判断安全窗口和买不买的取舍。记录从进入该关的玩家中有多少首通、失败原因及武器试用率，别用少量样本推全量难度。

**02 地下泵房起测算例。** 五波做 42＋48＋50＋55＋60 秒（4:15），分别教学带电区、冲车、组合和后续升级；关底战从约 1:00 有效战斗起测，五次整备按约 0:45 的主动选择估算，共约 6:00。整备不锁时间，Boss 不等计时结束才允许打死；若实测时间缩短，先看是否有独立战术决策可补，不拉长空波。危险区只在给足可见预警后通电，地图总保留可读的安全路线。

**验证方式。** 32＋33＋34＋35＝134 分钟，只有 14 分钟余量。01–03 就记录战斗、有效目标操作和主动整备三个计时桶，掉线恢复不双计。整篇在无广告、跳过可跳过对白、不刷旧关条件下，两名熟悉玩法的测试者分别用基础工具路线与正常首通工具路线完成，取两条有效路线中较短者；失败、等待、后台、刷关、广告均剔除，**少于 120 分钟不能过内容验收**。要补就补有新决策的任务或遭遇，不加血、不延长空档。

### 存档机制与跨设备恢复

**本地档已实现，云档未接入。** [战役档案](../creator-m0/assets/scripts/campaign/Campaign.ts)保存已首通关卡、已解锁武器和当前出勤标识；[关内快照](../creator-m0/assets/scripts/m1/Run.ts)保存关卡版本、局 ID、种子、波次、商店及已提交装配。两档各用 [A/B 双槽](../creator-m0/assets/scripts/platform/platform.ts)写入后回读，冷启选最新有效版本。通过 [`tt.setStorageSync`](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/api/javascript-api/data-caching/tt-set-storage-sync)存的是设备本地数据：强退恢复到最近检查点，不续精确战斗帧；清缓存、卸载或换机不能保证找回。

**本地结算及升级。** 先持久化胜利凭据（关卡 ID、唯一出勤 ID、规则版本），再提交首通和首通武器；下一关访问由前置首通状态派生，不另写一份。冷启动仅补交与当前出勤相符的有效凭据；已提交只恢复结算界面。永久档使用稳定 ID 和独立 schema，追加章节不重置旧进度；快照版本不兼容只提示重开当前关，损坏的永久档不按新档覆盖。旧 M2 胜利不自动导入；凭证流水还未接入本切片。

#### 云同步的数据边界

正式上线前计划接入跨设备备份，但不自建战斗服务器，也不阻塞 03–05 内测。云端首期只存同一抖音账号下的长期进度：已首通关卡、已解锁武器和已解锁蓝图（蓝图系统上线后）。记录稳定 ID、档案 schema 版本及服务侧更新时间。出勤标识、种子、波次、血量、整备、复活和可花费的凭证余额留本地；余额不做跨端相加，后续若同步需独立、可去重的发放与消费流水。云端存档不作排行榜、支付或防作弊凭证。

#### 同步与冲突处理

优先验证[抖音云数据库的小游戏存档方案](https://developer.open-douyin.com/docs/resource/zh-CN/developer/tools/cloud/develop-guide/local-develop/douyincloud-basedon-app/mini-game-how-to-use-cloud)。存档身份由平台可信账号确定，不接受客户端自行指定他人归属，不采集手机号或证件；未确认账号时先本地玩，不自动将游客档并给当前账号。首次绑定应明确导入对象；切号时隔离档案、取消或隔离上一账号未完成的请求，迟到回包不能写入当前账号。

先本地落盘，成功结算后把待同步的新增 ID 按账号持久排队；联网或回前台时读取、增量合并并重试。永久解锁只增不减，按集合去重合并，不能用较新时间戳或本地修订号整档覆盖。平台 [`addToSet`](https://developer.open-douyin.com/docs/resource/zh-CN/developer/tools/cloud/api-reference/cloud-database/client/sdk) 是候选原子操作；正式选用前必须验证同账号首次建档不会产生两条记录、两端并发不会丢更新。若客户端 SDK 无法满足，改用一层轻量云函数处理建档和合并，不改战斗逻辑。同步失败显示待同步，不能阻止进入关卡。

#### 存档验收与开通前置

- **本地**：在胜利凭据写入前、凭据写入后到档案提交前、档案提交后到结果显示前三处强退，分别验证不误发、只补发一次、只恢复界面；另测损坏档与扩章后旧档可读。

- **两台真机**：A 机离线完成 01，联网后 B 机用同一账号可进入 02 并装备电弧枪；让旧档与新档、两机同时写入和重复重试各跑一次，须保留全部有效进度且不重复发奖；换不同账号不能读到或上传前一账号的进度。B 不恢复 A 的在打波次。

- **开通**：先用目标 AppID 核对[抖音云审核与管理员权限](https://developer.open-douyin.com/docs/resource/zh-CN/developer/tools/cloud/develop-guide/active-douyin-cloud)，通过后用隔离开发环境做两机验证。资格未核实或云档未通过时，不对外承诺换机恢复；首章继续用本地档，正式上线前单列云档验收。

**分包与构建。** 主入口只带开局必要逻辑和共享小资源；01–05 为首章内容，后续章节按 [Cocos Asset Bundle](https://docs.cocos.com/creator/3.8/manual/zh/asset/bundle.html) 和[抖音分包](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/guide/basic-function/subpackages/basic)按需加载，章末空档可预取；下载失败可重试或回维修站，不回退已完成进度。所有规则随已审核的版本发布，不做远程热更代码；先用平台分包，不默认搭 CDN。按 [Cocos 抖音发布指南](https://docs.cocos.com/creator/3.8/manual/zh/editor/publish/publish-bytedance-mini-game.html)先以主包低于 4 MB、整包低于 20 MB 为工程约束，建议内部留余量到 3.5／18 MB，最终以当前控制台和实际产物为准。首章切片就实测分包、跨包依赖与弱网，不等第 20 关。

## 激励视频与商业验证

只有配置允许的第 2–5 波、非关底战死、当前局未成功复活时出现可跳过按钮。`requestId` 绑定当前死亡、关卡、波次和 attemptId。完整观看回调才原子保存「用掉本局复活」和波初快照；取消、无填充、超时、迟到与重复回调不得发奖。护送和中继必须恢复目标位置、血量／进度、随机流、商店和本局经济后才允许开广告；否则该关禁用。做同版本无广告对照。按[抖音激励视频接口](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/guide/open-ability/ad/incentive-ads)接真实回调，开发替身数据不得进入收入统计。

记录 `stage_start`、`stage_end`、`first_clear`、`weapon_equip`、`ad_eligible/request/shown/completed/revived`，带版本、关 ID、匿名分组、局 ID 与事件 ID。不给事件传证件、姓名或自由文本；先做诊断日志，测试与发布前确认实际事件出口与隐私披露。有真实 AppID／流量主能力再开平台测试；以平台成熟报表对账并区分展示、看完、复活和分成后收益。技术验收不等于盈利；自然量或受控试跑拿到 D1／D7 和按同来源激活用户的七日净广告收入，才考虑买量。

## 交付顺序与验收

| 里程碑 | 可以开工的任务 | 出口条件 |
| --- | --- | --- |
| A　01→02 技术闭环 | 锁 M2 对照；做工单配置、首通事务、选择电弧枪、版本兼容、真机分包骨架 | 两端能开 02；能用电弧枪；三处强退不丢不重；无广告可走全流程 |
| B　03–05 首章样板 | 破甲窗口、供电区、首个章末 Boss、首版叙事 UI、图集烘焙和计时表；同步核对云存档与广告的 AppID 接入资格 | 策划只改配置即可新增同模板关；无广告能通首章；记录实际每关人天和 Android/iOS 帧耗，再重估余量 |
| C　06–20 量产与终幕 | 护送与中继两模板、三场章末战、工具及故事；系统和内容拆开提交，按章收口 | 20 关可到达，无刷关门槛；四章首通奖完整，终幕复电，后续章能追加，广告异常有可玩回退 |
| D　发布候选与商业试验 | 两端完整通关、快路线计时、真广告回调、两机云档恢复、包体性能、弱网、测试通道、送审资料 | ≥120 分钟已测；双端不阻断；云档验收通过；能对广告与结算；提审与买量分别决策 |

粗排用于判断量级，不是工期承诺：01–03 约 8–12 人日，04–05 与作者工具约 4–7 人日；06–20 若首章测得每关配置、调平与冒烟约 1–2 人日，则这 15 关仅单关工作就约 15–30 人日，新增共享美术、目标逻辑、广告资格等待与返工另计；最后留 5–8 人日做候选版验证。先按首章吞吐重估，不按 AI 出图速度或关卡文件数排完工日。

**质量门。** 每个 PR 跑 Node 类型检查、战斗回归、内容与资产引用校验、固定种子和存档／回调异常用例。正式产物用固定 Creator 与配置，在有图形环境的 Mac/Windows 构建；[Cocos 命令行构建仍需要 GUI](https://docs.cocos.com/creator/3.8/manual/zh/editor/publish/publish-in-command-line.html)。发行候选关闭调试输出，实际 iOS 与中档 Android 测首启至可操作、分包弱网、最重战斗的帧耗和峰值内存、静音预警以及连打两关是否维持 30 FPS 目标。构建可发测试通道不等于能提审／营收；主体、备案、侧边栏、隐私和广告资格由账号控制台单独核对。

**第一批交付件**：一份关卡配置契约及引用校验器、一个可从 01 进 02 的战役分支、带强退和扩章演示的存档测试、一套泵房灰盒与美术母版、双端真机基线记录。之后才批量生成地图、肖像和关卡素材。本方案不改变 v0.3 的两小时下限，也不把可选内容计入主线。
