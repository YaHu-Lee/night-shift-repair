## 二、为什么现有文案一股“AI 味儿”？

逐行检查 `CampaignCatalog.ts`、`CampaignPressure.ts`、`Equipment.ts` 与 `M1Bootstrap.ts`，发现四类典型的 LLM 写作痕迹：

1. **“电报体事件摘要”冒充活人对白**
   - 原文例：`阿阮：二楼那户问我是不是跳闸。我一看，对面也黑了。` / `02:14，泵房才报过载。先断的电。切电原单在分站。` / `陈栖：签名下面有到期时间。撤单回执在下一页，一共三张。`
   - 病根：全篇用三五个字的碎短句＋句号硬切，像 AI 在总结剧情大纲，**阿阮和陈栖说话完全同质化，没有脾气、没有口癖、没有深夜抢修的狼狈与火气**。
2. **“市政大厅跑公章”式的行政剧情主线**
   - 原文 20 关反复围绕“查原单 → 对时间戳 → 找签名 → 拿回执 → 第一份授权 → 第二份授权 → 验双签”，跟主角扛着六把悬浮重工武器干翻暴走机械的爽快动作体验严重脱节；且从未讲清“为什么这些机器在追着修电工砍”。
3. **突兀的“AI 强行温情金句”**
   - 原文例：`阿阮：四号楼问你还在楼下吗。他们烧了壶水。`——前文通篇冷冰公文，结尾突然甩一个“烧了壶水”的温情意象，显得刻意又失真。
4. **“技术手册腔”界面与装备说明**
   - 原文例：`攻击间隔 −67 毫秒`、`波末零件回收率 +18 个百分点`、`选配件出勤`、`冲锋机亮灯，往旁边躲`、`离开亮起的车道，扫击一过就打`。
   - 病根：暴露内部帧率换算（2 tick = 67 ms），把玩家当 QA 测试员而不是夜班电工，所有战斗提示像同一个模板批量生成的复读机。

## 四、新 UI 架构对接清单（为阶段 3 Cocos UI 改造定标准）

阶段 1 纯 TS 内核（`assets/scripts/roguelite/`）已直接输出 UI 所需的全部结构化视图数据（ViewModel）：
1. **战斗 HUD 视图**：`hp / maxHp / armor / repair`、`level / xp / xpNext`、`wave / totalWaves / secondsLeft / stationName`、`parts / bagParts`、`synergies[]`（实时羁绊档位）、`bossView`（顶部血条 + 破防易伤状态 + 简短人话预警）。
2. **升级 4 选 1 视图**：`pendingLevelUps` 队列，每张卡含 `tier (1–4)`、`stat`、`label`、`deltaText`、`rerollCost`。
3. **4 格整备商店视图**：`offers[4]`（含 `locked`、`canAutoMerge` 升阶提示、`price`、`tags`、`tradeoff` 正负词条列表）、`weapons[6]`（含 `tier 1–4`、`sellPrice`、`canMergeWithSlot`）、`statsPanel`（8 项核心属性 + 实算减伤率/暴击率）、`rerollCost`、`nextWavePreview`（人话敌情提示）。
4. **结算复盘视图**：`damageByWeapon[]`（按 6 槽统计总伤与占比）、`synergiesReached[]`、`radioLine`（活人过关对白）、`nextAction`（直推下一章或高危加班）。
