# 《夜班修理局》战役 01→02 交接与验收

本批是 MVP 的第一段实现，不是完整 MVP。目标是复用六波单局，验证“打赢配电站 → 领到电弧枪 → 带新武器进入地下泵房”以及关间持久化。20 关、两小时、双端和真实广告仍是后续验收项目。

## 已交付

- **01 配电站**沿用 M2 六波与巡检机。第一次通关持久化打开 02 并授予电弧枪，不把旧 M2 胜利算作战役首通。
- **02 地下泵房**有六波：先教带电积水，再教冲车，之后组合。水区预警 24 tick（30 Hz 下为 0.8 秒），先预警后生效，两区轮换且中心留走位通道。关底用巡检机与轮换通电组合，是切片复用，不是后续独立章末 Boss。
- **电弧枪**作为已解锁时的开班选项，而非随机商店掉落。比扳手触距和普通连跳跨度大、基础可多跳一次，但同等单击伤害的攻击间隔更长；也可带原工具通关 02。02 的液压钉枪记录为后续进度，当前未制作其装备/攻击，也没有可玩的 03。
- **存档**：旧 M2 档、战役进度和战役每关快照分离。开局前注册 attempt ID；Run 的胜利快照先写入，战役首通和工具一起写，再根据首通推导下一关。恢复时会补做尚未提交的同一凭据。保存失败可重试，不认过期凭据。一局内进程中断回到最近已提交波次，不做逐帧恢复。
- **剧情**：两关各有工单和结单提示。第一章完整故事、20 关和实施计划见 [剧情大纲](CAMPAIGN-STORY-OUTLINE.md)、[策划 v0.3](GDD-v0.3.md) 和 [技术与制作 v0.2](TECHNICAL-DESIGN-v0.2.md)。

## 在普通 Linux 上复核

使用 Node 24：

```sh
npm ci
npm run typecheck
npm test
```

`tests/campaign.test.mjs` 覆盖错误版本／错误局凭据、档案写失败、冷启恢复、重复发奖及追加章节兼容；`tests/campaign-gameplay.test.mjs` 从实际战斗步进走 01→02，模拟档案提交中断，并分别验证 02 的电弧枪与扳手路线。模拟是确定种子的可达性证明，不是人测胜率，也不能拿来证明 120 分钟。仓库 Web 入口仍是 M0 压测页，不是这个战役 UI。

## 下一次在 Windows／Mac 打包

1. 用 Cocos Creator 3.8.8 打开 `creator-m0/`，打开 `assets/scenes/Campaign.scene`，不要用 M2 场景来判断战役。使用 `creator-m0/build-campaign.json` 对应的抖音竖屏调试配置。
2. 用抖音开发者工具导入生成的小游戏目录，在 Android 和 iOS 抖音中分别完成 01，重开，确认 02 和电弧枪可用；带电弧枪到 02 第一波，并检查商店仍可组成起手流派。再用扳手验证 02。
3. 分别在 01 胜利落盘前、胜利快照之后而进度事务之前（可用调试故障注入）、结单显示前杀进程；核对未持久化胜利不发奖、持久化后冷开补发一次、已提交只恢复显示。
4. 检查暂停、前后台、低端机帧耗、刘海／胶囊避让、积水预警形状与安全通道、阶段切换、出场触控、波间商店、断网或写盘失败。保存疑似损坏时不应把旧档当新档覆盖。
