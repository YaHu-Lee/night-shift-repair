# 《夜班修理局》游戏 E2E 与上线验收

Codex 负责代码审查、测试设计、执行、缺陷复现和证据汇总。项目经理评审游戏体验，例如新手是否看得懂、战斗是否有手感、成长节奏是否吸引人。当前渠道先做微信。抖音因软著暂缓，对应证据沿用原编号并记为延期。

- 对照上线清单接单或回填结果时，读[用例覆盖矩阵](references/coverage.md)和[上线验收清单](../../../docs/PRE-LAUNCH-CHECKLIST.md)。
- 实现浏览器测试、准备案例或排查不稳定时，读[实现方案与社区实践](references/implementation.md)。测画面动作或特效另读[游戏手感工作流](../night-shift-game-feel/SKILL.md)。测设备性能或音频中断另读[小游戏专项优化工作流](../night-shift-minigame-opt/SKILL.md)。

## 选择证据

1. 数值条件、全部组合和长局用 Node 单测及固定种子仿真。普通入口、Canvas 实际输入、状态迁移和存档恢复用 Playwright 驱动真实 Creator Web 包。布局、美术和特效用可重复画面或录像配合状态断言。
2. 构建、AppID、分包声明和资源指纹查真实微信候选包。原生分包、`wx` 存储、广告、分享、平台胶囊、系统音频中断、温升和峰值内存在对应微信环境补证。用户在真机未遇到模拟器退出是一次观察，长局性能仍按独立用例记录。
3. 有微信设备、测试权限和可用的自动化通道时，由 Codex 执行或采集技术证据。只能通过人触发的步骤明确写出需要的授权或设备动作，例如扫码、接听来电、提供一次受控性能录制。工程用例和技术判断仍由 Codex 负责。

## 执行与回填

1. 先核对当前构建来源。记录 Git HEAD、相关未提交改动、Creator 版本和包指纹。`npm run build:web` 只生成 Node 测试模块，Web E2E 用 Creator 3.8.8 的 Web 构建，发布验证用微信构建。[构建说明](../../../docs/COCOS-EDITOR.md)
2. 给每个案例独立的浏览器上下文和测试存档。`patrolDebug` 可布置视觉场景，`mockAd=1` 可实际操作模拟视频的看完、提前关闭和加载失败。正常入口验证至少用真实点击穿过被测转场。读调试快照等待状态并断言，触控通过 Canvas 发送。奖励、存档等副作用补查前后差额和重启后的结果。
3. 校验受影响的 Node 用例、对应浏览器用例及发布包。修改 `assets/scripts/` 时同步 Creator 副本和新增脚本的 `.meta`。验证 release 无调试探针和测试入口。记录实际跑过的浏览器、视口、种子、夹具模式及原生设备。
4. 每条结果按原清单 ID 回填。混合用例分开列 Web、包体和真机证据。一项的本轮必需证据齐全后再勾选。缺设备、权限、真实广告配置或难以复现时写明未覆盖动作、已有证据与阻塞原因。
5. 给项目经理只交付体验评审入口、几段代表性内容和待决体验问题。失败技术用例附最短复现和证据，由 Codex 继续处理。
